# 2026-09-11

## HaoNav 系统性体检 + 改造方案（方案文档已产出）

产出：`HaoNav-改造方案.md`（项目根目录）。仅出方案，未改代码。

### 实测事实（可复现，后续改造以此为基线）

- `npx vite build` → `dist/assets/index-*.js` **1,617 KB / gzip 359 KB，单 chunk 零分割**；`dist` 中**没有任何 CSS 文件**。
- 样式全部依赖 `cdn.tailwindcss.com` 运行时 JIT（实测 407,279 B / gzip 123,340 B，同步阻塞脚本）。**该 CDN 不可用 = 全站无样式**，属可用性缺陷而非优化项。
- bundle 内含 **1,657 处 lucide 引用 / 4,414 条 SVG path** = 整个图标库。根因：`components/Icon.tsx` 用了 `import * as LucideIcons from 'lucide-react'`，tree-shaking 失效。
- `@google/genai` 与 `jszip` 被打进主 chunk（编辑后台才用）。
- `index.html` 中同一段 site-config IIFE 重复 2 遍；importmap 指向 `aistudiocdn.com`（AI Studio 残留）。
- 根目录非源码资产 ≈ 1.16 MB（10 张 PNG 648 KB + docx 476 KB + 3 SVG 32 KB），只服务 README。

### 关键缺陷（本次体检新发现，非原代码注释所载）

1. **数据链路断裂**：`functions/api/link.ts` 写 KV 键 `app_data`，网页端读写 `haonav_links` → Chrome 扩展存的链接永远不显示。
2. **KV 绑定名两套**：`functions/*` 用 `env.CLOUDNAV_KV`，`api/*`+`edgefunctions/*` 用 `HaoNav_KV`；README 让用户绑 `HaoNav_KV` → 照 README 部署 CF 版本必 500。
3. **`IS_EDGEONE_ENV = hostname.includes('edgeone.app')`**：EdgeOne Pages 实际域名是 `*.edgeone.pages.dev` / `*.edgeone.cool`，判断恒为 false → 在 EdgeOne 上登录永远失败、数据永不上云、静默降级为纯本地。
4. **GET 鉴权可绕过**：`functions/api/storage.ts` 里 `password ? await verifyPassword(...) : true` → 不带 header 即全量公开读取；叠加 `Access-Control-Allow-Origin: *`。
5. **接管漏洞**：`verifyPassword()` 在 KV 无密码时会"把传入的密码存下来并返回 true" → 首个请求者成为站长。
6. **分类密码明文下发**：`Category.password` 随 JSON 返给浏览器，"私密目录"形同虚设。
7. **WebDAV 假成功**：`functions/api/webdav.ts` 只实现"存取 WebDAV 配置"，未实现任何 PROPFIND/PUT/GET 代理 → `check`/`upload` 恒返回 true，`download` 恒返回 null。用户以为有备份，实际没有。
8. **`saveLinks/saveCategories/saveSettings` = `loadAll()` + `saveAll()`**：先读后写，在最终一致的 KV 上存在真实丢写风险。Cloudflare KV 免费版仅 **1,000 写/天**。
9. **死代码 1,067 行**：`CategoryManagerModal`(328 行)、`CategorySortModal`(247 行) 均无入口（`setIsCatManagerOpen(true)`/`setIsCategorySortModalOpen(true)` 在代码中不存在）。
10. **其他**：`id: Date.now().toString()` 同毫秒撞车（`uuid` 被 import 却没用，`buffer` 未使用）；排序靠数组下标无持久化 order 字段；每次 render 执行 `categories.map(filter)` = O(分类×链接)；`vite.config.ts` 的 `define` 会把 `GEMINI_API_KEY` 内联进公开 JS；`vite.config.ts` dev 端口 3000 与 `eop-config.json` 的 5173 不一致；无 strict / ESLint / 测试。

### 用户三点硬要求

视觉尽量不变 · 运行快 · 编辑方便 · 只用 CF/EdgeOne/Vercel 免费套餐。允许推翻语言/框架/依赖/架构。

### 推荐方案（待用户确认后再实施）

- **方案 A**：Svelte 5 + Vite（双入口 `index.html` 前台 / `admin.html` 后台）+ Tailwind v4 构建时 + **Hono 单一 API**（`api/core.ts` 零平台依赖 + ≤10 行 adapter）+ KV 单文档 `nav:v1`（`rev` 乐观并发）+ LexoRank 排序 + 本地字母图标（0 请求）。
- 备选 **方案 B**：保留 React 19 就地加固（去 Tailwind CDN、修 `import *`、动态 import genai/jszip、预分组+防抖、懒渲染、重写后端）→ 首屏约 85–95 KB gzip。
- **删除**：WebDAV、Chrome 扩展生成器（生成代码有 `parentId` 写错等确定性 bug，改用 Bookmarklet）、两个死组件、多余两套后端、`uuid`/`buffer`、`@dnd-kit`、分类密码锁、根目录图片与 docx。

### 平台额度（2026-09 核实）

- Cloudflare Workers Free 100,000 请求/天；KV Free 100,000 读/天 · **1,000 写/天** · 1 GB · 单值 ≤25 MB → 首选，但写入必须合并成 PATCH。
- EdgeOne Pages：流量/请求不限量，Edge Functions 300 万请求/月，KV 1 GB 且**仅 Edge Functions 可调用** → 备选，函数额度更宽。
- Vercel Hobby 最紧且禁商业用途，KV 需外接 Upstash。

## 补充（同日）：框架选型与存储选型实测

用户追问「Svelte 5 / Next.js / Vue 3 哪个更优」与「KV / Blob / 数据库怎么选」。为回答，做了实测基准（`/tmp/fwbench` + `/tmp/nextbench`，可复现）。

### 框架运行时基线（生产构建，brotli = 实际传输）

| 框架 | raw | gzip | brotli |
|---|---|---|---|
| Next.js 16.3.4（App Router，单静态路由，默认模板） | 567.6 KB | 174.2 KB | **150.6 KB** |
| React 19.3.0 + ReactDOM | 217.4 KB | 67.3 KB | **57.9 KB** |
| Vue 3.5.42（runtime-only） | 51.9 KB | 20.7 KB | **18.9 KB** |
| Svelte 5.57.0 | 39.1 KB | 14.8 KB | **13.4 KB** |

- Next 测法：`next build` 后解析 `index.html` 实际引用的 7 个 script chunk 汇总。
- 其他测法：只 import 挂载入口（createRoot / createApp / mount），esbuild --bundle --minify，zlib 压缩。

### 单依赖体积（关键发现）

| 写法 | raw | gzip | brotli |
|---|---|---|---|
| `import * as LucideIcons from 'lucide-react'`（全量） | 822.9 KB | 191.4 KB | **146.0 KB** |
| 具名导入约 50 个图标 | 28.9 KB | 9.9 KB | **8.5 KB** |
| `@google/genai` + `jszip` 静态导入 | 454.7 KB | 94.9 KB | **75.2 KB** |

**体积归因**：现有产物 280 KB brotli = lucide 146 KB + genai/jszip 75 KB + React 57.9 KB = 279 KB。**整个包体几乎全是"框架 + 两处错误的 import"，业务代码占比接近 0** —— 改两个 import 即可砍掉 79%。

### 结论修正

- **框架：Vue 3 升为首选，Svelte 5 降为备选。** 原推荐 Svelte 的依据是"Vue 运行时约 34 KB 逼近 45 KB 预算"，实测 Vue 仅 18.9 KB，前提不成立。Vue 加应用代码约 34 KB，预算内有余量，且中文生态与 AI 生成准确率更好。Svelte 5 的额外坑：runes 语法 2024 年底才稳定，AI 容易写成 Svelte 4 的 `export let` / `$:`。
- **Next.js 出局**：其核心价值（SSR/SSG/ISR/RSC/文件路由/Server Actions）本项目一个都不用；上 Cloudflare 需 OpenNext 适配层，上 EdgeOne 需 static export 而**会废掉 API route**。需要 SEO 时的正解是 Astro 或方案 C，不是 Next。
- **存储是分工不是三选一**：主文档 → KV 单键；图标 → KV 单键 + 长缓存（不占 1,000 写/天的坑：每个域名只写一次）；快照备份 → Blob（强一致、无写次数压力）；数据库 → 暂不启用。
- **三个决定性认知**：① KV 写按 key 计费（官方文档 per-key），一次 PATCH 改 100 条 = 1 次写，1,000 写/天 ≈ 每天能保存 1,000 次；② KV 真正的陷阱是最终一致 ~60s 而非额度；③ 数据库的价值在查询，而本项目数据永远是整份读整份写，上 SQL 只会白付序列化 + 往返。
- **上 D1 的触发信号**（写进方案 4.8）：点击统计/访问记录等高频写入、多用户账号、服务端查询（筛选/分页/多标签）、链接量 10,000+ 需服务端检索、需要逐条修订历史。

方案文档 `HaoNav-改造方案.md` 已同步更新：新增 4.1.1（框架实测）、4.8（存储决策），并修正第 1/3/9 节与止血步骤的数字为实测值。

## 补充二（同日）：用户确认的四项决策

用户追问 4 个问题后，方案文档已按下列结论定稿：

1. **存储：只用 KV，Blob 与数据库都去掉。** 依据：KV 写按 key 计费，一次 PATCH 改 100 条 = 1 次写；推算实际用量约 60 次写/天（50 次保存 + 7 次快照 + 零星图标抓取），占 Cloudflare 免费 1,000 写/天 的约 6%。图标靠 `Cache-Control: immutable` 让浏览器只请求一次，省不出 KV 读取量，所以 Blob 无价值；快照每天 1 次写，Blob 的"写入无次数压力"也无意义。**引入 Blob 只会多一个要维护的绑定。**
2. **平台：国内访问为主 → EdgeOne Makers 首选；海外为主 → Cloudflare 首选；Vercel 不作目标平台。** 决定性因素不是额度（两家都够）而是中国大陆节点：EdgeOne 有大陆节点，Cloudflare/Vercel 无。因为架构已把平台差异收敛到 `api/adapters/`，**建议两家各部署一份做 A/B 实测**，增量成本几乎为零。注意 CF 的 1,000 写/天是唯一硬上限；自定义域名在国内 CDN 接入通常涉及备案，平台二级域名不需要。
3. **UI 允许重构，结构定为"左目录 + 右内容"**（与现状同构）。最快方案（已写入方案 6.1）：
   - 布局用纯 CSS Grid，零 JavaScript 计算
   - **`content-visibility: auto` + `contain-intrinsic-size` 是核心**（约 3 行 CSS 替代手写虚拟滚动，浏览器自动跳过视口外 section 的渲染/布局/绘制）
   - 预分组 `Map<catId, Link[]>` + 预建小写搜索索引（修掉当前 O(分类×链接) 重复计算）
   - 滚动联动改用 `IntersectionObserver`（当前是 scroll 事件里 getElementById + offsetTop，强制同步布局，且已被注释禁用）
   - 图标默认本地字母 SVG，零请求
   - section 级懒挂载列为**可选升级**，仅在实测滚动仍不流畅时才做（`content-visibility` 已覆盖 99% 场景）
   - 顺手增强：分类标题 sticky 吸顶、左侧分类项加计数徽章、`/` 聚焦搜索
4. **功能取舍定稿**：
   - **Chrome 扩展生成器 → 删除**。需求真实（一键存书签高频），但"站点现场生成扩展 + 手动加载已解压扩展"这个方式有四个死结（生成的代码有 bug、需手动重载或上架审核、站点更新后无自动升级、500 行模板字符串无法维护）。**替代：先做 Bookmarklet（约 1 小时），用满一个月确认高频后再做独立扩展仓库（约 1 天）。**
   - **AI 猜分类 → 删除**。分类仅 10–20 个，下拉框人眼选比等 AI 快，AI 猜错还要人工改回，净成本为负。
   - **AI 批量补描述 → 保留但必须改造**：移到服务端、改批量（一次 20–50 条，而非现在一条一请求）、仅在 `/admin` 按需触发。这是唯一真正省时间的 AI 功能。
   - 若用户不愿为 AI 付费，两个都删也成立（用批量编辑 + 从 `<title>` 自动填标题替代），且 `@google/genai` 的 75.2 KB brotli 可直接从包中消失。
   - 站外搜索简化：固定引擎 + 前缀触发，不做完整 CRUD 管理面板。
   - 新增：每日 KV 快照、重复检测、死链检测。

## 补充三（同日）：最终决策锁定

用户已下达三项最终决策，方案文档 `HaoNav-改造方案.md`（717 行）已全部同步：

1. **框架确定用 Vue 3**（不再是"首选/备选"二选一）。文档 4.1 已标注"✅ 已确认"。
2. **导航逻辑确认**（写入 6.2）：与现有行为一致，用户无需重新学习操作。
   - 「全部链接」（默认）→ 置顶区 + **所有分类** section
   - 「任一具体分类」→ 置顶区（**跨分类的全部置顶链接**）+ **仅该分类** section
   - 站内搜索时只显示命中的分类，置顶区隐藏
   - **对性能设计的关键影响**：「全部链接」既是默认视图也是最重的视图（所有卡片都要渲染），`content-visibility` 主要服务于它；单分类视图天然很轻，无需优化。优化目标因此非常集中。
3. **AI 与浏览器插件全部删除**（不只是"改造"）。连带影响已核实：
   - AI：删 `services/geminiService.ts` + `@google/genai`（实测 358.3 KB raw / **49.4 KB brotli**）+ `types.ts` 的 `AIConfig`/`AIProvider` + `App.tsx` 的 `aiConfig`/`AI_CONFIG_KEY` + `LinkModal` 的 `aiConfig` prop + 原定的 `/api/ai/enrich` 接口
   - 插件：删扩展生成器（`SettingsModal` 内约 660 行模板）+ `jszip`（**唯一使用点是 `SettingsModal.tsx:729` 打包扩展文件**，实测 96.4 KB raw / **26.3 KB brotli**）
   - **合计净省 75.8 KB brotli，且不需要写任何替代代码**
   - `SettingsModal.tsx` 从 1,092 行瘦身到约 230 行（`ai` 与 `tools` 两个 tab 整体删除）
   - 新链接录入路径改为：打开本站添加 + 导入浏览器书签 HTML。**Bookmarklet 明确不在本次范围内**，仅作为未来可选项记录在文档里。
4. **R2 / Blob 确认不需要**（写入 4.8）。理由：图标靠浏览器 `Cache-Control: immutable` 只请求一次，省不出 KV 读取；快照每天 1 次写、7 份约 2.8 MB，KV 空间与写额度都远远够用；而引入它要多一个绑定、多一处凭证、多一套 SDK、多一层跨平台适配，收益为 0；R2/EdgeOne Blob 还需单独开通（CF R2 可能要求绑卡），与"只用免费套餐"冲突。
   - **真正需要对象存储的触发条件**：新增用户上传附件类功能（自定义图标原图、原始 HTML 归档、导出 zip）、数据量超 KV 的 1 GB、一天 10 万次以上图标读取。
   - **必须守住的约束**：KV 单值上限 25 MB，图标**绝不能**以 data URL 内联进主文档（会让每次保存重传数 MB），必须独立成 key。
